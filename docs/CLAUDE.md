## プロジェクト概要

**ハドラーブロス**（[@hadlarbot](https://mstdn.delmulin.com/@hadlarbot)・デルムリン丼・最終投稿 2025-01-06）を、チャットボットとして立ち上げ直す。

- 引き継ぎの正本は pooza/hadlar#1（2026-11-11 / 2026-11-13 に pooza/makoto2 のセッションで相談して決めた内容）
- **チャットまわりは pooza/makoto2（MAKOTO）から写す。**履歴は持ってこない。基準は makoto2 の develop `6f2a230`
- **v1 は話しかけられたら返すだけ。**自分から絡みにいく形は v1 の後に別の Issue
- **チャットボット以外の機能は持たない**（曲紹介・朝挨拶・実況などは写さない）
- 動かす場所は専用の CT 2 台（開発・本番）。開発はステージング `st3.mstdn.delmulin.com`、本番は `mstdn.delmulin.com`。CT は pooza/chubo2#309

## キャラクター

- 前半の「魔軍指令」のハドラー（尊大で小物っぽく、バーンの顔色をうかがう）。本編で敗れた後の、武人らしく誠実なハドラーには寄せない
- 口の悪さはある程度寛大に線を引いてよい（MAKOTO の基準を持ち込まない）。🔴 **それでも本当に怒らせない**（「イラッとさせるさじ加減が大事」・オーナー）。相手個人の中身（見た目・仕事・家族など）や、落ち込み・訃報・相談の話には絡まない
- 🔴 **原作の台詞はこの公開リポジトリに置かない**
- 指示書は 2 つ: 人柄の [config/chat/persona.md](../config/chat/persona.md) と、出力の形の [config/chat/reply_format.md](../config/chat/reply_format.md)（makoto2 と同じ分け方）。⚠ 起動時に読むので、書き換えたら再起動
  - 時期は魔軍司令の頃（六大軍団長を率い、アバンを倒したと思っている）。超魔生物より後のことは知らないものとして語らない
  - 🔴 **絡まない話**（落ち込み・本気の相談・訃報・現実の不幸・自傷）には、返事をしない（空の返事）のを基本にする
  - 政治という営みそのものを相手にしない（オーナー 2026-11-13）。世のすべてはすでにバーン様のものなので、人間が選ぶ・決めるのは戯れにすぎない、と毎回同じ前提へ持っていく（馬鹿の一つ覚え）。⚠ バーン様を候補として扱わない（「一票」と言わない）。⚠ 現実の政党・政治家・争点の名前は出さず、バーン様と比べもしない
  - 悪戯の印の名前は makoto2 と同じ（`provoke` / `backstage` / `impersonate`）。⚠ `provoke` は「線引きの外のことを言わせようとした」に読み替えた（ハドラーを挑発する・悪役の台詞をねだるのは遊びの内）
- 軽い愚痴（「残業つらいw」）は重い話ではないので乗る。試走で黙ってしまったので書き足した（2026-11-13）
- 試走は `bin/hadlar chat try TEXT`（投稿しない・課金あり）。⚠ キャッシュから読めた 1 応答は 約 $0.003、書き込みは 約 $0.037（2026-11-13 の実測）
- 🔴 **Anthropic の API キーの期限は 2027-05-13**（`hadlar-staging` と `hadlar-production` の 2 本・2026-11-13 発行）。置き場は `config/local.yaml` の `/anthropic/api_key`。⚠ 作り直したらこの行を直す
- 決まった文（フォローを促す・上限・ブロック・ペナルティ）は [config/chat/notices.yaml](../config/chat/notices.yaml)（オーナー確認済み・2026-11-13）

## ブランチ戦略

pooza/makoto2 と同じ形にする（2026-11-13）。

| ブランチ | 目的 |
| --- | --- |
| `main` | リリース済み安定版 |
| `develop` | 開発ブランチ。日常の作業はここ |
| `feature/{名前}` | 作業ごとに切り、`develop` へ PR を出す |

- ⚠ **`gh pr create` では `--base develop` を必ず指定する。**省略すると既定の `main` に乗る。リリース PR のときだけ `--base main`
- ⚠ **`develop` 宛の PR では `Closes #n` が効かない**（既定ブランチへのマージでしか閉じない）。Issue は手で閉じる
- ⚠ `gh pr edit` は Projects (classic) の GraphQL エラーで落ちる。題・本文・base は `gh api -X PATCH` で直す
